# キーマップ

> ステータス: 合意済み（2026-09-25）

モーダル編集をプラグインでどう実現するかを決める。最初の標準プラグインは Helix 風キーマップ（`plugins/helix`、プラグイン名 `helix`）。ほかのエディタの操作感をどう足すかは [base.md](base.md)。

## コアとキーマッププラグインの分担

| コア | キーマッププラグイン |
|------|------------------------|
| キーを入力スタックに流す。Ctrl-g だけは予約キーとして自分で受け取る | 入力スタックのいちばん下の層として、Ctrl-g 以外のすべてのキーを受け取る |
| 選択、トランザクション、undo の履歴 | モードと、押しかけのキー（`g` を押して次を待っている状態など） |
| 縦移動、スクロール、検索、書記素の境界 | 単語移動や文字検索（`f`）のような、テキストだけで決まる移動 |
| カーソルの形とステータスラインを描く | モードに応じて、カーソルの形とステータスラインの中身を指定する |

コアはモードを知らない。「ノーマルモード」「挿入モード」は、キーマッププラグインの内部状態にすぎない。

## Helix 風キーマップの内部構造

### 状態

プラグインが持つ状態は次のとおり。

- 現在のモード（ノーマル・挿入・選択）
- 押しかけのキー列と、回数の前置き（`3w` の `3`）
- レジスタ（`y` でコピーした内容）
- 直前の検索パターン、直前の文字検索（`f` / `t`）
- 挿入を始めたかどうか（undo の単位をまとめるため）

### キーの解釈

1. モードごとにキー列からアクションへの木を持つ。既定の配置に、設定の上書きを重ねて作る。
2. キーが届いたら、押しかけのキー列に足して木をたどる。
   - 途中の節なら、続きを待つ。
   - 葉ならアクションを実行し、キー列を空にする。
   - 木にないなら捨てる。
3. 挿入モードでは、木にない文字キーをそのまま挿入する。

### アクション

アクションは 2 種類ある。

- **組み込み**: 単語移動や削除のように、プラグインの中で実装するもの。すべて `helix.<名前>` のコマンドとしても登録し、他のプラグインや設定から呼べるようにする。
- **コマンド**: `buffer.save` や、他のプラグインの `lsp.definition` のように、名前で呼ぶもの。

名前は Helix のコマンド名（`move_next_word_start` など）に合わせる。

### 複数選択

移動や編集は、すべての選択範囲に同じように適用する。

- 移動では、各範囲の新しい位置を計算し、`set-selection` を 1 回だけ呼ぶ。
- 編集では、全範囲の `edit` を 1 つのトランザクションにまとめる。

### undo の単位

- ノーマルモードの編集（`d`、`c`、`p` など）は、1 回ごとに `new-step`。
- 挿入モードでは、入ってから最初の編集を `new-step`、以降を `merge` にする。挿入全体が 1 手になる。

### モードの知らせ方

モードが変わったら、次の 3 つを行う。

1. `set-cursor-shape` でカーソルの形を変える（ノーマルはブロック、挿入はバー）。
2. `ui.set-status` でステータスラインのモード表示を更新する。
3. `input.set-mode` でモードを知らせる（挿入モードなら `typing`）。他のプラグインがモードに合わせて動けるようにするため（`mode-changed` イベントで届く）。

端末に貼り付けたものは、挿入モードでは打ったように各カーソルに入れる。ノーマルと選択モードでは `pass` を返し、コアが各選択の前に入れる（[plugin-api.md](plugin-api.md) の「入力」）。

### プラグインのバッファのキー

プラグインのバッファ（[plugin-buffers.md](plugin-buffers.md)）が決めたキーは、ノーマルモードで数を打っていないときに、helix のキーより先に効く。ただし、次のキーは helix のまま。プラグインの作者は、これを避けてキーを選ぶ。

- 動き: `h` `j` `k` `l` `w` `W` `b` `B` `e` `E` `g` `f` `F` `t` `T` `%` `[` `]`、数、矢印、`Home` `End` `PageUp` `PageDown`
- 検索: `/` `?` `n` `N` `*`
- 選択とコピー: `v` `x` `X` `;` `,` `y` `m` `z`、`Space`（リーダー）、`:`
- Ctrl: `C-w`、`C-d` `C-u` `C-f` `C-b`、`C-o` `C-i`
- `Esc`

`plugins/helix.toml` の `[settings.keys.*]` で決めたキーは、バッファのキーより先に効く。

## 設定

`~/.config/nib/plugins/helix.toml` の `[settings]` に書く。キーの書き方は Helix の `[keys.*]` と同じにする。タブ幅やインデントはコアの設定（`[core]`）なので、ここには書かない。

```toml
[settings.keys.normal]
"C-s" = "buffer.save"
g = { a = "goto_last_accessed_file" }   # 表は前置きキーになる

[settings.keys.insert]
j = { k = "normal_mode" }
```

ドットを含まない名前は、helix プラグイン自身のコマンドとして解釈する。実装済みのコマンドの範囲であれば、Helix の設定をそのまま貼り付けて使える。vision.md の「互換を目指さない」は vim / emacs に対するもので、これはキーマッププラグインの中での便宜。

M4.1 での実装:

- キーの書き方は Helix と同じ。1 文字（`a`、`G`）、修飾つき（`C-s`、`A-x`、`S-tab`）、名前つきのキー（`ret`、`esc`、`space`、`tab`、`backspace`、`del`、`up`、`down`、`left`、`right`、`home`、`end`、`pageup`、`pagedown`、`F1` など）。
- ドットを含む名前（`buffer.save`、`picker.files`）は、その名前のコマンドを呼ぶ。
- helix プラグイン自身のコマンドは、Helix のコマンド名で書く（`move_next_word_start` など）。中では、そのコマンドの既定のキーを押したのと同じに扱う。名前と既定のキーの対応は、helix プラグインの表（`plugins/helix/src/keys.rs`）にある。
- 知らない名前やキーの書き間違いは、起動時にメッセージで知らせ、その割り当てだけを使わない。1 か所の書き間違いでキーマップ全体が動かなくなるのを避けるため。
- 表は前置きキーになる。前置きキーを押すと、ほかの前置きキーと同じく、次に押せるキーを右下に出す。
  - 挿入モードの前置きキー（`j = { k = "normal_mode" }`）のあとに表にないキーを押したときは、前置きキーの文字を入れてから、押したキーを普通に扱う。`jj` と打ったつもりが消えないようにするため。
- 割り当ては既定のキーより先に見る。同じキーの既定の動作は隠れる。

## M1 で実装するキー

Helix の既定の配置のうち、nib 自身のソースを編集するのに必要なものに絞る。

| 分類 | キー |
|------|------|
| 移動 | `h` `j` `k` `l`、矢印キー、`w` `b` `e` `W` `B` `E`、`f` `t` `F` `T` |
| ジャンプ | `gg` `ge` `gh` `gl` `gs`、`Ctrl-d` `Ctrl-u`、`Ctrl-f` `Ctrl-b` |
| 選択 | `x`、`%`、`;`、`,`、`Alt-;`、`C`、`s`、`v`（選択モード） |
| 編集 | `i` `a` `I` `A` `o` `O`、`d` `c` `y` `p` `P`、`r`、`>` `<`、`J` |
| undo | `u` `U` |
| 検索 | `/` `?` `n` `N` `*` |
| 対応括弧 | `mm`、`mi` / `ma`（括弧と引用符。テキストだけで判定する） |
| バッファ | `gn` `gp` |
| 回数 | `3w`、`5j` などの前置き |
| コマンドライン | `:w` `:q` `:q!` `:wq` `:o <path>` |
| 挿入モード | 文字、`Enter`（前の行のインデントを引き継ぐ）、`Backspace`、`Tab`、矢印キー、`Esc` |

M1 での実装上の注意:

- `w` `b` `e` は、Helix と同じく通った範囲を選択する。単語の終わりにいるときは、次の文字から選ぶ。
- `f` `t` `F` `T` は、カーソルのある行の中だけを探す。
- 括弧（`mm` `mi` `ma`）はテキストだけで対応を取り、引用符は行の先頭から順に組にする。
- `Ctrl-d` などのページ送りは、表示を動かしたあと、カーソルをスクロールの余白の外へ押し出す。コアの自動追従と打ち消し合わないようにするため。

M1 のあとに回すもの:

- ファイル選択などのスペースメニュー → M3.3
- LSP を使う操作（`gd` など）
- 構文木を使う操作（`maf`、`Alt-o` など）→ M2.2
- システムのクリップボード
- `.` による繰り返し
- 名前つきレジスタ（`"a`）
- 押しかけのキーの候補表示（ポップアップとタイマーが必要）→ 待たずに出す形で M2.3

## M2.2 で実装するキー

構文木の API（[plugin-api.md](plugin-api.md) の「構文木」）を使うもの。構文木のないバッファでは、テキストオブジェクトと選択の拡大は何もせず、括弧は M1 と同じくテキストで判定する。

| 分類 | キー |
|------|------|
| テキストオブジェクト | `mi` / `ma` のあとに `f`（関数）、`t`（型）、`a`（引数）、`c`（コメント）、`T`（テスト） |
| 次・前のオブジェクト | `]f` `[f`、`]t` `[t`、`]a` `[a`、`]c` `[c`、`]T` `[T` |
| 選択の拡大・縮小 | `Alt-o`（`Alt-↑`）で親のノードへ広げ、`Alt-i`（`Alt-↓`）で戻す |
| 兄弟のノード | `Alt-n`（`Alt-→`）で次、`Alt-p`（`Alt-←`）で前の名前つきのノードを選ぶ |
| 対応括弧 | `mm`、`mi` / `ma` の括弧と引用符を、構文木で判定する |

- テキストオブジェクトは、言語の `textobjects` クエリの `<名前>.inside` / `<名前>.around` を使う。`mi` / `ma` はカーソルを囲むもののうち最も小さいものを選ぶ。
- `]f` などは、カーソルより後ろ（`[` は前）で始まる最初のものを選ぶ。回数を付けるとその数だけ進む。引数（`a`）は `inside`、ほかは `around` を選ぶ。
- `Alt-o` は、選択とちょうど同じ範囲のノードがあればその親へ、なければ選択を覆う最も小さいノードへ広げる。`Alt-i` は `Alt-o` で広げる前の選択に戻す。`Alt-o` を使っていなければ、最初の名前つきの子へ縮める。
- `mm` は、カーソルの下の括弧が構文木で組になっていれば（親のノードの最初と最後の子）その相手へ動く。`mi(` などは、カーソルを囲み、最初と最後の子がその括弧であるノードを探す。どちらも見つからなければ、テキストで判定する（コメントの中の括弧など）。

## M2.3 で足す表示

装飾とポップアップ（[plugin-api.md](plugin-api.md) の「UI」）を使うもの。

- **対応する括弧の強調**: カーソルが括弧の上にあるとき、組の相手を `ui.cursor.match` で強調する。テキストを変えなかったキーのあとは、その場で更新する。テキストを変えたキーのあとは、構文木の解析が終わってから（`syntax-updated` を受けてから）更新する。キーの処理の中で構文木を読むと、裏で走っている解析を待つことになるため（[architecture.md](architecture.md) の「解析のスレッド」）。構文木で組が分かるときだけ強調し、テキストでは探さない。対応の相手がないとファイルの終わりまで探すことになり、打鍵のたびに払うには重いため。
- **キーの候補**: `g`、`m`、`mi` / `ma`、`]` / `[` を押したとき、次に押せるキーと説明を右下のポップアップに出す。Helix と同じく待たずに出し、次のキーで閉じる。`f` / `t` / `r` のように任意の文字を待つものには出さない。

## M3.3 で足すキー

- `Space` で始まるキーを足す。`Space` を押すと、ほかの前置きキーと同じく候補を右下に出す。
  - `Space` は helix のリーダー（[base.md](base.md) の「リーダー」）。helix 自身が持つのは `Space w`、`Space y`、`Space p`、`Space P` だけで、ほかはプラグインの `plugin.toml` の `[keys]` から来る。押したときに `input.leader-keys()` で読み、候補にはコマンドの説明を出す。ぶつかって負けたキーは、候補の最後に「taken」として出す。
  - `Space f`: ファイル選択（`picker.files`、picker の `[keys]`）
  - `Space e`: ディレクトリの一覧（`files.open`、files の `[keys]`。[files.md](files.md)）
  - `Space ?`: コマンドの一覧（`picker.commands`、picker の `[keys]`）。名前と説明で絞り込み、選んだものを引数なしで呼ぶ。Helix の command palette と同じ位置。

ファイル選択そのものは、`picker` プラグインが入力スタックに層を積んで受け持つ。ファイルの一覧は、コアの `files.walk` で得る（M4.4 までは git / rg で得ていた）。

| キー | 動作 |
|------|------|
| 文字、`Backspace` | 絞り込みの文字列を編集する |
| `↑` / `↓`、`Ctrl-p` / `Ctrl-n` | 候補を選ぶ |
| `Enter` | 選んだファイルを開く |
| `Esc` | 閉じる |

## M3.4 で足すキー

LSP プラグイン（[lsp.md](lsp.md)）のコマンドを呼ぶ。

| キー | コマンド |
|------|----------|
| `gd` | `lsp.definition`（定義へ移動） |
| `Space k` | `lsp.hover`（カーソル位置の説明。lsp の `[keys]`） |
| 挿入モードの `Ctrl-x` | `lsp.complete`（補完の候補を出す） |

補完の一覧を開いているあいだは、helix が `Ctrl-n` / `↓`（次）、`Ctrl-p` / `↑`（前）、`Tab` / `Enter`（確定）を一覧への操作として送る（[plugin-api.md](plugin-api.md) の「文字を打つ欄のない一覧」、[lsp.md](lsp.md) の「補完」）。ほかのキーはふつうに効き、一覧は閉じる。

## M4.2 で足すキー

| キー | 動作 |
|------|------|
| `.` | 直前の挿入を繰り返す（Helix と同じく、挿入モードに入ったキーから `Esc` までをもう一度行う） |
| `"` と 1 文字 | 次の `y` `d` `c` `p` `P` が使うレジスタを選ぶ |

- `.` は、挿入モードに入ったキー（`i` `a` `I` `A` `o` `O` `c`）と、挿入モードで押したキーを覚えておき、押し直す。回数を付けると（`3.`）その回数だけ繰り返す。
- レジスタは文字ごとに、選択ごとの文字列の並びを持つ。既定は `"`。`_` は捨てる先で、`d` で消しても何も残らない。
  - `+` はシステムのクリップボード（M4.5）。`y` で書き、`p` / `P` で読む。選択が複数あれば、改行でつないで 1 つの文字列にする。

## M4.5 で足すキー

| キー | 動作 |
|------|------|
| `Space y` | 選択をシステムのクリップボードへコピーする（`"+y` と同じ） |
| `Space p` / `Space P` | クリップボードの中身を選択の後ろ / 前に貼る（`"+p` / `"+P` と同じ） |

helix プラグインは、このために `clipboard` の権限を宣言する。

## M4.7 で足すキー

`Ctrl-w` と `Space w` を、分割表示の前置きキーにする（Helix と同じ）。押すと、ほかの前置きキーと同じく候補を右下に出す。

| キー | 動作 |
|------|------|
| `v` | 左右に分ける（`view.split` の vertical） |
| `s` | 上下に分ける（horizontal） |
| `w` | 次のビューへ |
| `h` `j` `k` `l` | 左・下・上・右のビューへ |
| `q` | フォーカスしているビューを閉じる |
| `o` | ほかのビューを閉じる |

## コマンドライン

`:` で始まるコマンドラインは、helix プラグインの一部として実装する。解釈は共有ライブラリ（`plugins/base-kit` の `cmdline`、[base.md](base.md)）が持つ。

1. `:` を押すと `ui.panel` を作ってパネルを開き、パネルにカーソルを置く。
2. 入力中のキーは helix プラグインの内部状態で振り分け、パネルの中身とカーソルを更新する。helix はもともと入力スタックのいちばん下でキーを受け取っているので、層を積み足す必要はない。
3. `Enter` で入力を解釈してコマンドを呼び、パネルを閉じる（リソースを捨てると閉じる）。`Esc` と、空のときの `Backspace` は何もせず閉じる。

| 入力 | 呼ぶコマンド |
|------|--------------|
| `:w`（`:write`） | `buffer.save` |
| `:o <path>`（`:open`、`:e`、`:edit` も同じ） | `buffer.open` |
| `:q` / `:q!`（`:quit` / `:quit!`） | `editor.quit`（`:q!` は `{"force": true}`） |
| `:wq` / `:x` | `buffer.save` のあと `editor.quit` |
| `:bc` / `:bc!`（`:buffer-close` / `:buffer-close!`） | `buffer.close`（`:bc!` は `{"force": true}`） |
| `:config` / `:config <name>` | `config.open`（名前があれば `{"plugin": name}`） |
| `:config-reload` | `config.reload` |
| `:<名前> [引数]`（`:lsp.definition`、`:buffer.open path=src/main.rs`） | その名前のコマンド。引数は `key=value` を空白で区切って並べるか、JSON をそのまま書く。`key=value` の値は、JSON として読めるもの（`3`、`true`）はその値、ほかは文字列。なければ `{}` |

- `:`、`/`、`?`、`s` の欄は、コアの入力欄（[plugin-api.md](plugin-api.md) の「入力欄」）で開く。helix が自分で解釈するのは Helix の入力欄のキーで、ほかはコアの既定に任せる: `C-c`（取り消し）、`C-n` / `C-p`（次、前）、`C-w` と `A-Backspace`（前の単語を消す）、`C-u` / `C-k`（先頭まで、末尾まで消す）、`C-a` / `C-e`（先頭、末尾へ）、`A-b` / `A-f`（単語単位で動く）。picker の検索欄など、ほかのプラグインの欄でも同じキーが効く。
- 名前を打っている間は、上の短い名前と、登録されたすべてのコマンドのうち、打った文字で始まるものを、説明と一緒に入力欄の上に出す。`Tab` で次の候補を入力欄に入れ、`Shift-Tab` で前に戻る。
- コマンドを呼んだあと、幅 0 の選択（ほかのバッファに移ったときなど）は、ノーマルモードの形（1 文字のブロック）に直す。

失敗したときは、コマンドが返したエラーを `ui.show-message` で表示する。

コマンドラインを独立したプラグインに分けるかどうかは、他のプラグインからもコマンドラインを使いたくなった時点で考える。

## ほかの編集モデルでも成り立つか

この仕組みが Helix 専用になっていないかを、vim 風キーマップで確かめておく。

- vim のカーソルは、幅 1 の選択として表せる。ビジュアルモードは、Helix の選択モードと同じく選択を広げるだけ。
- `d` を押して移動を待つ状態（operator-pending）は、プラグイン内のキー列の木と状態で表せる。`dw` は「`w` の移動範囲を計算して、その範囲を削除する」になる。
- `.` による繰り返しは、プラグインが直前の操作を記録すればよく、コアの支援は要らない。

コアに足りないものは見当たらない。vim 風キーマップは、作る必要が出たら別のプラグインとして作れる。
