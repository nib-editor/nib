# ベースプラグイン

> ステータス: 提案（2026-09-27）

helix 以外の操作感（vim、Emacs、nano）を足すにあたり、「エディタの操作感を丸ごと持つプラグイン」をベースと呼び、その作り方と、ベース同士で何を共通にするかを決める。[keymap.md](keymap.md) の Helix 風キーマップは、最初のベースになる。

## ベースとは

- ベースは、1 つのエディタの操作感を丸ごと持つプラグイン。キーの割り当て、モード、編集の作法、コマンド入力（`:` やミニバッファ）まで含む。
- 標準のベースは `helix`、`nano`、`vim`、`emacs` を予定する。
- **同時に動くベースは 1 つだけ。** 複数が動くと、どちらもいちばん下の入力の層としてキーを取り合う。

エディタごとに分けるのは、同じ名前の機能でも作法が違うため。1 つの共通のベースにまとめると、どれかに無理が出る。

| | helix | vim | Emacs | nano |
|---|---|---|---|---|
| 単語移動 | 単語を選択する | カーソルを動かす | 単語の終わりへ | カーソルを動かす |
| コピーの置き場 | レジスタ | 名前付きレジスタ | キルリング | カットバッファ |
| 繰り返し | マクロ | `.` とマクロ | `C-x z` とマクロ | なし |
| コマンド入力 | `:` | `:`（`C-r` でレジスタを入れる、など） | `M-x` のミニバッファ | 下の行の問い（`^O` のファイル名など） |

## 選び方

`config.toml` の `[core]` で 1 つ選ぶ。既定は `helix`。

```toml
[core]
base = "vim"
```

- ベースかどうかは、プラグインの `plugin.toml` に書く（`base = true`）。コアは、`[core] base` で選ばれたもの以外のベースを読み込まない。使わないベースのぶん、起動の時間とメモリが増えない。
- 選ばれたベースが見つからない、または読み込みに失敗したら、`helix` で起動し、そのことをメッセージで知らせる。ベースがないとキーで何もできないため。
- ベースを変えるのは、この 1 行だけで済む。キーの上書きは各ベースの設定に置くので（次の節）、ベースを行き来しても、それぞれの上書きが残る。

## キーの上書き

各ベースの設定（`plugins/<ベース>.toml`）の `[settings.keys.<モード>]` に書く。いまの helix と同じ形。

```toml
# plugins/vim.toml
[settings.keys.normal]
"C-s" = "buffer.save"
g = { d = "lsp.definition" }   # 表は前置きキーになる

# plugins/emacs.toml（モードがないので global）
[settings.keys.global]
"C-x" = { "C-r" = "picker.recent" }
```

- `config.toml` には書かない。ベースを変えるたびにキーの設定を書き換えずに済む。
- モードの名前はベースが決める（vim は `normal` / `insert` / `visual`、Emacs は `global`、nano は `global`）。
- キーの書き方（`C-x`、`M-f`、`S-tab`、前置きキーの表）と読み方は全ベースで同じにし、共有ライブラリが読む。
- 右辺は、そのベースのアクションの名前か、コマンドの名前（`buffer.save`、`lsp.definition`）。

## コマンド入力はベースが持つ

`:` の入力欄やミニバッファは、コアには置かない。キーの作法がエディタごとに違うため。

- vim の `:` は `C-w` で単語を消し、`C-r` でレジスタを入れ、上下で履歴をたどる。
- Emacs のミニバッファは `C-a` / `C-e` で端へ、`M-p` / `M-n` で履歴、`TAB` で補完、`C-g` で抜ける。
- nano は下の行で問い、`^C` で取り消す。

共有ライブラリは、キーを持たない入力欄の部品（文字列、カーソル、履歴、補完の候補）だけを持つ。どのキーでどの操作をするかと、panel への描き方はベースが決める。

ベース以外のプラグインが文字の入力を求める場合（将来の LSP のリネームなど）は、それが必要になった時点で、選ばれたベースが実装するコマンドの名前（`base.prompt` など）を決める。入力の作法はベースのものになる。いまはそういうプラグインがないので、決めない。

## 共通にするもの: 共有ライブラリ

ベース同士の共通部分は、ビルドのときに各ベースに取り込む Rust のライブラリに置く。実行時のプラグインにはしない。

- 同時に動くベースは 1 つなので、実行時に共有するものがない。
- プラグインをまたぐ呼び出しが増えず、1 キーの処理が今と同じ速さのまま。
- プラグイン API の外なので、1.0.0 のあとでも作り替えられる。実行時のプラグインのコマンドにすると、それ自体が公開 API になる。

置き場所は、はじめは標準プラグインのワークスペースの中（`plugins/base-kit/`、プラグインではないライブラリ）にする。外のベースの作者が使いたくなったら、SDK として出すかを考える。Go で書くベースは使えないが、標準のベースはすべて Rust なので、当面は困らない。

いまの helix（約 2,700 行）の振り分けの目安:

| 中身 | 行数 | 置き場所 |
|------|------|----------|
| 文字と行の読み出し、単語の境界、文字探し（`f`）、括弧の対応 | 約 400 | ライブラリ |
| tree-sitter のテキストオブジェクト、選択の広げ縮め | 約 170 | ライブラリ |
| キーの書き方の読み書き、`[settings.keys.*]` の上書き | 約 250 | ライブラリ（アクションの一覧はベース） |
| 次のキーの候補の表示 | 約 50 | ライブラリ（中身はベースが渡す） |
| 入力欄の部品、`:w` `:q` `:config` などの ex コマンドの解釈 | 約 150 | ライブラリ（vim と helix が使う。Emacs は `M-x` でコマンドの名前を呼ぶ） |
| 編集の適用、貼り付け、インデントの増減、行の連結、検索の折り返し、置き換え | 約 550 | ライブラリ |
| モード、キーの割り当て、押しかけのキー、選択が先に来る動き方、レジスタ、繰り返し | 約 1,100 | helix |

線の引き方: ライブラリは「位置を求める」「編集を組み立てる」まで。「その位置でカーソルを動かすか選ぶか」「消したものをどこに置くか」はベース。レジスタとキルリングのように作りの違うものは、無理に共通にしない。

## 進め方

1. helix からライブラリを切り出す。helix の動作は変えず、今のテストで確かめる。
2. `plugin.toml` の `base` と `[core] base` を足す。
3. nano を作る。ライブラリだけで足りるかを確かめる役。
4. vim と Emacs を作る。
5. 標準で同梱するかは、各ベースの大きさを測ってから決める（一つで数百 KB の見込み）。
