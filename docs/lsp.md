# LSP

> ステータス: 実装済み（2026-09-26、M3.4）

LSP（Language Server Protocol）のクライアントを、標準プラグイン `lsp` として作る。コアは LSP を知らない。プラグインは外部プロセスの API でサーバーを起動し、イベントで受け取った出力を JSON-RPC として読む。

## 範囲

M3.4 で作るもの:

- サーバーの起動と初期化、ファイルの同期（`didOpen` / `didChange` / `didSave` / `didClose`。`didClose` は、コアの `editor.buffer_closed` を受けて送り、そのファイルの診断も忘れる）
- 診断: 範囲に下線を引き、行末にメッセージを出し、ステータスラインに件数を出す
- ホバー: helix の `Space k` で、カーソル位置の説明をポップアップに出す
- 定義へ移動: helix の `gd`

M3.4 の続きで作るもの:

- 補完（下の「補完」）

## コマンド

| コマンド | 内容 |
|----------|------|
| `lsp.hover` | カーソル位置の説明をポップアップに出す（helix の `Space k`） |
| `lsp.definition` | 定義へ移動する（helix の `gd`） |
| `lsp.complete` | カーソルの前の語の補完を出す（helix の挿入モードの `Ctrl-x`） |
| `lsp.status` | 動いているサーバーを、言語ごとに `rust ready` のような 1 行で返す（`starting` / `ready` / 落ちたものは `stopped`）。キーには割り当てていない。使うときは `plugins/helix.toml` の `[settings.keys.normal]`（[keymap.md](keymap.md) の「設定」）に、`space = { l = "lsp.status" }` のように書く |

## サーバーの設定

`plugins/lsp.toml` の `[settings.servers.<言語>]` に、起動するコマンドを書く。言語の名前は、言語プラグインの `[[languages]]` の `name`（`syntax.language` が返すもの）。

```toml
[settings.servers.rust]
command = ["rust-analyzer"]

[settings.servers.python]
command = ["pyright-langserver", "--stdio"]
```

- 既定では rust（`rust-analyzer`）、go（`gopls`）、python（`pyright-langserver --stdio`）を設定しておく。設定に書いた言語は、既定を置き換える。
- サーバーは、その言語のファイルを初めて開いたときに起動する。起動できなければ、その言語では一度だけメッセージを出して、以降は起動を試みない。
- サーバーは言語ごとに 1 つ。ルートはエディタの作業ディレクトリ（`editor.working-directory`）。

## 診断の受け取り方

診断には 2 つの受け取り方があり、両方に対応する。

- push: サーバーが `textDocument/publishDiagnostics` で送ってくる。
- pull: サーバーが初期化の応答で `diagnosticProvider` を返したら、クライアントが `textDocument/diagnostic` で取りに行く。rust-analyzer は、型の誤りのような自分で見つけた診断をこちらで返す（`cargo check` の結果は push で送ってくる）。
  - 開いたときと、編集が 200 ms 止まったときに取りに行く。打つたびに要求しないよう、タイマーで待つ。
  - サーバーから `workspace/diagnostic/refresh` を頼まれたら、開いているファイルすべてについて取り直す。
- push と pull の結果はファイルごとに別々に持ち、合わせて表示する。片方が来ても、もう片方は消さない。

## 位置の数え方

- 初期化で `positionEncodings` に `utf-8` と `utf-16` を挙げる。サーバーが `utf-8` を選べば、コアの位置（バイト）をそのまま使う。
- `utf-16` のときは、位置を送るたびにその行を読んで数え直す。
- 変更の同期は、`utf-8` なら `buffer-changed` の変更の列をそのまま差分として送る（行と列はコアが付けている）。`utf-16` なら、変更前の行がもう読めないので、全文を送る。

## コアに足すもの

- `editor.working-directory()`: ファイルの URI を作るのに、作業ディレクトリの絶対パスが要る。バッファのパスは開いたときの書き方（相対パスのこともある）なので。
- 行末の注記（`ui.set-notes`）: バッファの位置に結びつけた文字列を、その行の末尾に出す。装飾と同じく名前空間ごとに差し替え、位置は編集に合わせてコアが動かす。行の中に割り込まないので、縦移動や横スクロールの計算は変わらない。

## 補完

- 候補の一覧はポップアップで、カーソルの前の単語の始まりの下に出す。
- 開き方:
  - 挿入モードの `Ctrl-x`（helix プラグインが `lsp.complete` を呼ぶ）
  - 自動: 挿入モードで識別子の文字を 2 文字以上打つか、`.` / `::` を打ったあと、打鍵が 150 ms 止まったら要求する。打つたびに要求しないよう、タイマーで待つ。挿入モードかどうかは、`helix.mode_changed` イベントで知る。
- キーの受け持ち: 一覧を開いているあいだだけ、LSP プラグインが入力スタックに層を積む。
  - `Ctrl-n` / `↓` と `Ctrl-p` / `↑` で候補を選び、`Tab` / `Enter` で確定する。これらのキーは下に回さない。
  - `Esc` は一覧を閉じてから下に回す（挿入モードも抜ける）。
  - ほかのキーは下に回す。キーマップが文字を入れると `buffer-changed` が届くので、その時点の単語で候補を絞り直す。単語の外に出たら閉じる。
- 候補は、サーバーが返した一覧を、カーソルの前の単語の始まりから見た接頭辞で絞る（大文字と小文字は区別しない）。並びは `sortText`、なければ `label` の順。
- 確定したら、候補の `textEdit` があればその範囲を、なければ単語の始まりからカーソルまでを置き換える。スニペット（`insertTextFormat` が 2）は、`$1` や `${1:x}` の目印を取り除いて文字だけを入れる。

## メッセージの読み書き

- サーバーの標準出力は `process-output` イベントで少しずつ届くので、`Content-Length` ヘッダーで区切れるまでためる。
- 要求には id を振り、何の要求だったか（ホバー、定義など）を覚えておく。応答が来たら、その時点のバッファに対して処理する。応答を待つあいだも、エディタは止まらない。
- 標準エラー出力は捨てる。サーバーが終了したら、メッセージを出して、その言語のサーバーを止まったものとして扱う。

## テスト

実際のサーバーは CI の 3 つの OS にそろえにくいので、テスト用の偽のサーバーを使う。テストの実行ファイルが、特定の引数で起動されたときだけ LSP サーバーとして振る舞う（`harness = false` のテスト）。偽のサーバーは、`error` を含む行に診断を出し、ホバーと定義に決まった答えを返す。
