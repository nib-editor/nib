# ファイルの一覧とディレクトリを開くこと

> ステータス: 合意済み（2026-09-29）。

`nib <ディレクトリ>` で開けるようにし、ディレクトリの中身を眺めてたどる一覧（Emacs の dired、vim の netrw に当たるもの）を標準プラグインとして足す。あわせて、設定のファイルを作りやすくする。

## 2 つの道具

ファイルを開く道具は 2 つにし、どちらも標準で入れて、好きに組み合わせる。

| プラグイン | 役 | 向くとき |
|------------|----|----------|
| picker（今ある） | 名前で探す。下のファイルを深さによらず全部並べ、打った文字で絞り込む | 開きたいファイルの名前をなんとなく知っている |
| files（新しい） | 1 つのディレクトリの中身を、バッファに並べる。中に入り、上に戻ってたどる | 何があるか分からない所を見る、構造をつかむ |

## ディレクトリを開く

`nib <ディレクトリ>` と、ディレクトリを渡されたときに何をするかは、`config.toml` の `[core]` に、呼ぶコマンドとして書く。

```toml
[core]
# A directory given to nib runs this command with {"path": "<dir>"}.
# "picker.files" picks a file under it instead.
open-directory = "files.open"
```

- コアは、ディレクトリを受け取ったら、このコマンドに `{"path": "<絶対パス>"}` を渡して呼ぶだけで、どのプラグインかは知らない。自作のプラグインのコマンドも書ける。
- 作業ディレクトリは変えない。
- そのコマンドがない（プラグインが無効など）ときは、「open-directory: no command named files.open」のように知らせ、空のバッファで始める。
- ファイルとディレクトリを混ぜて渡したら、渡した順に開く。

`picker.files` は `{"path": "<dir>"}` を受け取り、その下のファイルを並べる（今までどおり、なければ作業ディレクトリ）。

### 設定のディレクトリ

- コアのコマンド `config.open-directory` で、設定のディレクトリ（`~/.config/nib/`）を、上の `open-directory` のコマンドで開く。
- helix と vim のコマンドラインでは `:config-dir`、コアメニューでは「Open the settings directory」。
- files で開けば、そこから `plugins/` に入り、各プラグインの設定のファイルを開ける。

## files プラグイン

### 一覧

```
── /Users/q0tzly/.config/nib/ ──────────────────────
/Users/q0tzly/.config/nib/
  ../
  plugins/
  themes/
  config.toml      2.1K
```

- 1 行目はディレクトリの絶対パス、2 行目からが中身。`../`、ディレクトリ（`/` を付ける）、ファイルの順で、それぞれ名前の順。隠しファイルも出す（設定のディレクトリのように、隠れたものを見たいことが多いので）。
- ファイルには大きさを付ける（`812`、`2.1K`、`3.4M`）。更新の日時は出さない（WASI からは地域の時刻が分からないので、UTC で出すと読み違える）。
- バッファの名前はディレクトリの絶対パス（末尾に `/`）。ディレクトリごとに 1 つのバッファ。中に入る、上に戻るときは、同じビューに新しいディレクトリのバッファを出し、前の一覧は閉じる（一覧のバッファが積もらないように）。
- 色は装飾で付ける。ディレクトリは `ui.popup.key` ではなく、新しい `ui.directory` を使う（テーマで変えられるように）。
- 書き換えはできない（持ち主が `set-editable` しない）。名前の変更や削除は、あとで足す。

### キー

どのベースでも同じキーにする。vim と helix が手放さないキー（[vim.md](vim.md)、[keymap.md](keymap.md) の「プラグインのバッファのキー」）を避けて選ぶ。

| キー | コマンド | すること |
|------|----------|----------|
| `Enter` | `files.enter` | カーソルの行を開く。ディレクトリなら中に入り、ファイルなら同じビューに開く（一覧のバッファは残る） |
| `-` | `files.up` | 上のディレクトリへ（vim の vinegar と同じ） |
| `+` | `files.create` | 名前を聞いて、そのディレクトリに新しいファイルを開く |
| `q` | `files.close` | 一覧を閉じる |

- リーダーの下の `e`（helix と vim の `Space e`、Emacs の `C-c e`、nano の `M-E`）に `files.open` を置く。helix 本家の `Space e`（ファイルの一覧）と同じ。
- `files.open` は、引数がなければ、表示中のファイルのディレクトリを開き、カーソルをそのファイルの行に置く。ファイルでなければ作業ディレクトリを開く（Emacs の `dired-jump`、vim の `:Explore`）。
- 動き、検索、コピーは、ふつうのバッファと同じく、ベースのキーで効く。

### 新しいファイル

- `+` で、入力欄に名前を打つ（`plugins/vim.toml` のように、下のディレクトリも書ける）。`Enter` でそのパスを開く。ファイルは、保存したときに作られる。
- 保存するとき、コアは、ないディレクトリを作る（`buffer.save` の決まりを変える。今は失敗する）。
- ディレクトリだけを作ることは、今はしない（ファイルを作れば、その途中のディレクトリはできる）。

### コアに足すもの（API）

一覧に要るのは、1 つのディレクトリの中身と種類と大きさ。`files.walk` は、下を全部たどり、.gitignore と隠しファイルを除くので合わない。WASI のファイル API は、作業ディレクトリの下しか渡していない。

```wit
interface files {
    record dir-entry {
        name: string,
        /// A directory, or a link to one.
        directory: bool,
        /// In bytes; 0 for a directory.
        size: u64,
    }
    /// What `dir` holds, hidden files too, sorted by name. Needs the
    /// "fs-read" capability.
    %list: func(dir: string) -> result<list<dir-entry>, string>;
}
```

- `walk` と同じく `fs-read` の権限で、どのディレクトリも読める（名前と大きさだけで、中身は読めない）。
- 1 段だけなので、呼び出しの中で待って返す。
- 関数を足すだけなので、古いプラグインはそのまま動く。0.x の決まりでパッチを上げ、`nib:plugin@0.7.1`、SDK は 0.7.1。マニフェストの `api` は `"0.7"` のまま。

## 設定のファイルを作りやすくする

プラグインの設定のファイル（`~/.config/nib/plugins/<name>.toml`）は、標準プラグインのものも含めて、今でも置けば効く。コアメニューの「Open its settings」や `:config <name>` で開けば、なければ雛形の入った状態で開き、保存すると作られる。足りなかったのは次の 3 つ。

1. **雛形の `[settings]` が空だった。** 読み込み方（`enabled`、`timeout-ms` など）はコメントで入るが、そのプラグイン独自の設定（vim の `leader`、lsp の `servers` など）は、文書を読まないと分からなかった。
   - プラグインは、自分の設定の例を `settings.example.toml` としてプラグインのディレクトリに置ける。中身は、`[settings]` の下に入る行を、コメントにしたもの。
   - コアは、雛形の `[settings]` の下にそれを差し込む。標準プラグインは全部置く。`nib plugin pack` も同梱する。
2. **雛形が入るのは `config.open` で開いたときだけだった。** 設定のディレクトリの `config.toml` と `plugins/<name>.toml` を、どう開いても（files の `+`、`:e`、`buffer.open`）、ファイルがなければ雛形を入れる（保存はしない）。
3. **`nib config init` は config.toml と helix.toml しか作らなかった。** 使っているベース（`config.toml` の `base`、なければ helix）の分を作る。

## 版

- nib は 0.12.1（足すだけで、今の使い方は変わらない）。
- API は `nib:plugin@0.7.1`。SDK の Rust と Go は 0.7.1 のタグを打つ。

## 入れないもの

- 横に細く出すファイルの木（サイドバー）。分割の幅を決める API などが要る。
- 一覧の中での名前の変更、削除、コピー、印を付けてまとめて操作すること（dired の `R`、`D`、`m`）。
- 更新の日時と権限の表示。
